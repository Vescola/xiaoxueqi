## 已实现：心跳超时检测（方案 A）

用户选择「保留 HEARTBEAT 命令 + 补超时检测」，未删除心跳机制。改动：

- `src/net/clientsession.h/.cpp`：新增 `QDateTime m_lastActive`、`lastActive()`、`touch()`、`close()`；
  构造函数与 `onReadyRead()` 中刷新活跃时间；`close()` 先 `disconnectFromHost()`，
  若仍处于非 UnconnectedState（半开连接无法靠 FIN 关闭）则 `abort()`。
- `src/net/servercore.h/.cpp`：新增 `QTimer *m_hbTimer` 与槽 `onHeartbeatCheck()`；
  定时器在 `start()` 中创建（此时对象已在业务子线程），周期 30s（`kHeartbeatCheckIntervalSec`）；
  `stop()` 中停止。扫描时**先收集 idle 列表再统一断开**——`close()` 会同步触发
  `disconnected` → `onSessionDisconnected` 修改 `m_clients`，边遍历边断开会导致迭代器失效。
- `config.ini.example`：`HeartbeatTimeoutSec` 由死配置变为生效，补注释（<=0 不启用）；
  标注 `MaxPendingConn` 预留未接入。

本机无 Qt/g++ 环境，未做编译验证，仅静态核对符号一致性。

## 遗留待办（本次未动）

1. **订单联动**：连接被踢掉/断开时，该连接上的 `charging` 订单不会结算，会永久悬挂。
   启用超时检测后该风险更频繁，需在 `onSessionDisconnected` 中联动处理，
   并与 `handleStopCharge` 的 payOrder 失败路径一起改。
2. P0 未修：时区混用（start_time 用 SQL CURRENT_TIMESTAMP=UTC，end_time 用本地时间，
   导致计费时长多 8 小时）、结算失败锁死账号、changePassword 绕过 PasswordUtil、
   registerUser 错误码失真、管理员明文口令、后台重启不检查在充订单。
3. P1 未修：SQLite 并发写未开 WAL/busy_timeout、验证码可重放、devCode 回传、
   nextOrderNo 用 COUNT+1 会撞主键。

## 后续：用户要求撤回心跳检测改动（已回滚）

4 个源文件 + `config.ini.example` 已精确还原到改动前状态，代码回到「只回应不检测」。

**重要教训（下次务必注意）**：本仓库工作区相对 HEAD(65f7949) 存在**用户自己的未提交改动**
（EVChargingServer.pro、appconfig.h、passwordutil.h、databasemanager.cpp、main.cpp、
launcherwindow.cpp、logindialog.ui 等均已是 M 状态）。因此**绝不能**用
`git checkout -- <file>` / `git restore` 做回滚，那会把用户此前的工作一起清除。
正确做法是逐处反向编辑，或用 `git diff` 只摘出本次的 hunk 反向 apply。

回滚后全项目 grep 已确认无 `m_hbTimer` / `onHeartbeatCheck` / `lastActive` /
`QTimer` / `touch` / `ClientSession::close` 残留。

心跳相关结论仍然成立，若将来重做需一并处理：
- 断开连接时该连接上的 `charging` 订单不会结算，会永久悬挂；
- 客户端心跳发送间隔必须小于 `HeartbeatTimeoutSec`，否则正常连接被误踢；
- `MaxPendingConn` 仍未接入。

## 最终决定：彻底删除心跳功能（方案 C，已完成）

注意事项：
