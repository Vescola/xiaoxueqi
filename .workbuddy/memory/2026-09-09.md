## 充电桩项目：客户端/服务端"连接后立即断开"问题

### 诊断结论
1. **"新连接 → 连接断开"不是故障**，是客户端的短连接模型：
   `ServerApiClient::request()` 中 `QTcpSocket socket;` 为局部变量，
   一次请求建一条连接，return 时析构即断开。服务端日志必然成对出现。
2. **真正的功能性 Bug**：客户端 `ping()` 发 `HEARTBEAT_REQ=0x6001`，
   服务端 `EVChargingServer/src/common/protocol.h` 未实现 0x6000 段心跳，
   `servercore.cpp` 的 switch 走 default → 回 `ERROR_RESP(0x9FFF) 未知命令码`。
   客户端 `request()` 见到 ERROR_RESP 直接 return false ⇒ **ping 恒为 false**。
   `mainwindow.cpp` 中 6 处 `if (m_serverApi && m_serverApi->ping(...))`
   （:108 / :310 / :367 / :396 / :432 / :476）全部走 else，
   导致注册/登录/充电/充值等业务**从未真正打到服务端**，一直跑本地 SQLite 演示模式。

### 改动（仅限 ChargingUserClient_ - 1，用户要求"只删心跳"）
- `clientprotocol.h`：删除 `HEARTBEAT_REQ(0x6001)` / `HEARTBEAT_RESP(0x6002)` 两个常量。
- `serverapiclient.cpp:39-55`：`ping()` 由"发心跳包"改为**纯 TCP 连通性探测**
  （connectToHost + waitForConnected(1200) + disconnectFromHost），不再发任何业务报文。
  `mainwindow.cpp` 6 处调用点与 `m_serverMode` 逻辑保持原样，未做其它改动。

## 充电桩项目：计费逻辑修复（分三步，本次只做第 1、2 步）

### 背景诊断
- "不管输入多少度都结算 408.07 度"：两个 Bug 叠加
  1) 客户端输入的 targetKwh 从未参与计量，服务端按 `功率×真实时长×0.85` 结算；
  2) start_time 用 SQLite `CURRENT_TIMESTAMP`(UTC) 写入，`QDateTime::fromString`
     按本地(UTC+8)解析 → 时长被放大 8 小时。60kW 桩 → 408.07 度（验算吻合）。
- 客户端充电动画是"固定 40 步×350ms=14 秒"，与真实功率无关（worker 未接收 powerKw）。

### 本次改动（第 1、2 步）
1. **时区**：`EVChargingServer/src/db/databasemanager.cpp` `createOrder` 的
   `start_time` 由 `CURRENT_TIMESTAMP` 改为绑定 `QDateTime::currentDateTime().toString("yyyy-MM-dd HH:mm:ss")`（本地时间）。finishOrder 的 duration_minutes 随之自动正确。
2. **客户端动画**（`ChargingUserClient_ - 1`）：
   - `chargingworker.h`：`start()` 增加 `double powerKw` 参数 + 成员 `m_powerKw`。
   - `chargingworker.cpp`：新增 `constexpr double kSimSpeedUp = 150.0`；
     每步电量 = `powerKw * kSimSpeedUp / 3600 * 0.2`；定时器 350ms → 200ms。
     效果：120kW 桩 = 5 度/秒（60 度 12 秒）；7kW 慢充约 0.29 度/秒。
   - `mainwindow.cpp`：`invokeMethod` 增加 `Q_ARG(double, m_selectedPile->power)`。

### 待用户自行完成（第 3 步，服务端结算）

  `energyKwh = target_kwh`、`amount = energyKwh × unit_price`（等价于
  目标度数 × 电价，倍率在数学上会抵消）。
